# Рекомендательная система

Проект посвящен построению пайплайна рекомендательной системы на данных сервиса доставки. Задача — предсказание порядка товаров на экране корзины. В качестве основной метрики используется NDCG@10.

**Датасет:** Датасет с курса ШАД по рекомендательным системам (взаимодействия пользователей с товарами Яндекс.Лавки).

---

## Подготовка данных

В качестве взаимодействий рассматривались события добавления в корзину (`AT_CartUpdate`), которые очищались от дублей.
*   **Train:** 132,226 уникальных пар (user, item), 2,211 пользователей, 13,106 айтемов.
*   **Validation:** 432 пользователя с целевыми корзинами.
*   **Cold-start:** Для пользователей без истории (или с пустыми предсказаниями) применялся fallback на Top-500 популярных товаров.

---

## Кандидат-генерация

Для обогащения признакового пространства были обучены несколько моделей кандидат-генерации. Их скоры и производные метрики использовались в качестве фичей для финального ранкера.

### 1. Item-to-Item (i2i)
Построение матрицы схожести айтемов на основе совместных покупок.
*   **Cosine Similarity:** Матрица взаимодействий L2-нормализуется по столбцам. Обеспечивает высокое покрытие каталога, но уступает в точности.
*   **Raw Co-occurrence:** Сырая матрица `X.T @ X`. Дает высокий Recall, но сильно «схлопывает» каталог (низкое покрытие).

### 2. Alternating Least Squares (ALS)
Коллаборативная фильтрация на основе библиотеки `implicit`. Была проведена оптимизация гиперпараметров:
*   **Factors (эмбеддинги):** Протестированы размеры от 64 до 400. Оптимальным выбран **256**.
*   **Regularization:** Перебор от 0.001 до 0.5 показал, что параметр почти не влияет на качество. Оставлено значение `0.01`.
*   **Alpha (уверенность в позитивах):** Оптимальным оказалось значение `10`.

### 3. Two-Tower Models
Были протестированы различные архитектуры двухбашенных моделей и лоссов для их обучения
*   **Base Two-Tower (MF):** Классическая матричная факторизация с обучаемыми эмбеддингами пользователя и айтема.
*   **Mean Two-Tower:** Башня пользователя формируется как среднее эмбеддингов айтемов из его истории.
*   **Функции потерь и негативы:**
    *   Full Softmax (по всему каталогу).
    *   Uniform Softmax (сэмплирование K=1024 случайных негативов).
    *   In-batch Softmax (негативы из батча) + LogQ-correction (коррекция на частоту айтема для борьбы со смещением).

## Feature Engineering (для CatBoost)

Для обучения ранкера использовались фичи, полученные от моделей кандидат-генерации, а также счетчики и контекстные признаки.

### А. Фичи от кандгенов
Для каждой пары (user_id, product_id) вычислялись:
*   **Скоры (dot product):** `als_score`, `v5_score` (Two-Tower), `v6_score` (MF).
*   **Нормы и косинусы:** `als_cosine`, `v6_cosine` — нормализованные скоры. *По результатам Feature Importance, косинусы от ALS и Two-Tower вошли в топ самых важных фич, так как убирают влияние популярности из скора.*
*   **Произведения норм:** Дают информацию о «силе» (популярности) эмбеддингов пользователя и товара.

### Б. Счетчики (Counters)
Рассчитывались по различным временным окнам: `all`, `30d`, `7d`, `1d`.
*   **User:** Число просмотров, кликов, корзин, покупок, уникальных товаров/категорий. Дни с первого/последнего действия.
*   **Item:** Число просмотров, кликов, корзин, покупок, уникальных юзеров. Дни с первого/последнего просмотра.
*   **User-Item:** Число взаимодействий конкретного пользователя с конкретным товаром. Дни с последнего взаимодействия.
*   **User-Category:** Число взаимодействий пользователя с категорией товара.

### В. Контекстные и производные
*   `source_type`, `city_name`, `product_category` (категориальные).
*   `hour_of_day`, `day_of_week` (из timestamp).
*   **Ранги и отношения:** Ранги скоров ALS/MF внутри выдачи, доля взаимодействий пользователя с товаром к общим.

## Ранжирование (CatBoostRanker)

Обучение финальной модели ранжирования на подготовленных данных.

### Эксперименты с датасетом:
*   **Undersampling:** Оставляли только выдачи, где был хотя бы один `AT_CartUpdate`. Внутри выдачи: все позитивы, топ-10 просмотров по позиции, топ-3 клика. *(1.81M строк)* — лучший Private Score.
*   **Расширение данных:** Брали все выдачи с `AT_CartUpdate`. *(5.43M строк)* — лучший Public Score.
*   **Удаление шумных фич:** Убрали фичи с нулевой важностью. Метрика упала

**Функции потерь (Losses):**
*   `YetiRank` — основной выбор (дает лучший NDCG).
*   `PairLogit` — дала чуть худший результат на валидации.

## Выводы

**Итоговый результат:** В ходе работы удалось достичь значения метрики NDCG@10: **0.3936 (Private Score)**.

1. **Использование кандидат-генераторов в качестве признаков:** Добавление скоров и производных от моделей (ALS, MF, Two-Tower) в ранкер обеспечивает существенный прирост итоговой метрики.
2. **Влияние нормализации:** Признак `als_cosine` (нормализованный скор ALS) вошел в топ-5 по Feature Importance, поскольку он снижает влияние популярности товаров на итоговую оценку.
3. **Сравнение стратегий сэмплирования:** Использование undersampling (1.8M строк) снижает переобучение и показывает более высокий результат на Private Score. В то же время обучение на полном датасете (5.4M строк) дает лучший результат на Public Score.
4. **Эффективность ансамблирования:** Усреднение рангов (rank-average) двух моделей, обученных на разных стратегиях сэмплирования, позволяет достичь наилучшего результата (Public Score: 0.3965).
